# backend/tests/audit

**감사에서 나온 결함들의 회귀 하네스.** 각 검사는 그 결함이 **원래 재현되던
방식**을 그대로 다시 시도하고, 아직 재현되는지를 판정한다.

```bash
python backend/tests/audit/verify_findings.py
```

```
FIXED F1a       temp-save racing publish writes into a PUBLISHED version
...
{'FIXED': 14, 'OPEN': 0, 'N-A': 0}
```

| 판정 | 뜻 |
|---|---|
| `FIXED` | 그 결함이 더는 재현되지 않는다 |
| `OPEN` | 아직 재현된다. 증거가 붙는다 |
| `N-A` | 심볼이나 엔드포인트가 옮겨가 검사를 수행하지 못했다 → **사람이 봐야 한다** |

`OPEN` 이 하나라도 있으면 **exit code 1** 이므로 빌드 게이트로 쓸 수 있다.
`N-A` 는 0 을 반환하지만 조용히 넘기면 안 된다 — 검사가 죽은 것이지 통과한 게 아니다.

## 왜 pytest 가 아닌가

`pytest.ini` 는 `test_*.py` 만 수집하므로 이 파일은 스위트에 잡히지 않는다.
의도한 것이다. 스위트는 **코드가 오늘 의도대로 동작하는지**를 증명하고, 이
하네스는 **예전에 어떻게 잘못됐었는지**를 고정한다. 후자는 리팩터링 중에 조용히
되살아나는 쪽이라 판정을 분리해 두는 편이 낫다.

## 옵션

| 옵션 | 용도 |
|---|---|
| `--only F1a,RULE-psn` | 특정 검사만. 펀치리스트 확인용 |
| `--report PATH` | UTF-8 JSON 리포트 위치 (기본: OS 임시 디렉터리) |
| `-v` | FIXED 항목의 증거까지 출력 |

콘솔이 cp949 라 표준출력은 ASCII 로 강제하고, 한글이 섞인 상세 증거는 JSON
리포트에 UTF-8 로 쓴다 (`CLAUDE.md` 의 mojibake 주의사항과 같은 이유).

## 안전성

- 모든 쓰기는 **`iai_audit_verify_<pid>`** 라는 일회용 DB 안에서만 일어나고,
  끝나면 `finally` 로 지운다. 프로세스마다 이름이 달라 동시 실행해도 겹치지 않는다.
- **`iai-test` 와 `dsep_iai` 에는 절대 쓰지 않는다.** `iai-test` 를 보는 검사는
  `information_schema` 와 `SELECT` 뿐이다.
- 접속 정보는 `tests/conftest.py` 와 같은 기본값을 쓰고 `WP_AUDIT_DB_*` 환경변수로
  덮어쓸 수 있다. DB 에 못 붙으면 exit code 2 로 끝난다.

## 이 판정이 **덮지 못하는 것**

`FIXED` 를 어디까지 믿어야 하는지가 이 문서에서 가장 중요한 부분이다.

- **F1a/F1b 는 동시성 부하 시험이 아니다.** 문제의 인터리빙을 단일 프로세스에서
  결정론적으로 재연한다. 가드를 검증하는 데는 맞는 단위지만, 실제 경합 하에서의
  동작이나 처리량은 말해 주지 않는다.
- **잠금 순서(WP → 버전) 교착은 시험하지 않는다.** 순서는 `version_service` 에
  주석으로만 고정돼 있고, 반대로 잡는 경로가 새로 생겨도 이 하네스는 못 잡는다.
- **`NEW-1` 의 드리프트 검사는 한 방향뿐이다.** ORM 에는 있는데 DB 에 없는 컬럼만
  본다. 타입·nullable·인덱스 차이나 **DB 에만 있는 잔여 컬럼**은 못 잡는다.
  반대 방향은 `db/verify.py` 의 스키마 드리프트 검사가 담당한다 — 둘 다 돌려야
  한다.
- **`R3` 의 판정 기준이 바뀌었다.** 원래 발견은 "미배정 행은 항상 경계" 였는데,
  `plan.md` §0.2-4 가 그것을 정정했다 — 경계인 것은 맞지만 **한 블록 한가운데의**
  회색 행에서 Phase 를 만들면 그 블록이 쪼개진다. 예전 검사는 전부 미배정인 보드만
  보았고 그 보드에서는 옛 규칙과 새 규칙의 답이 같아 **변별력이 없었다.** 지금은
  허용되어야 하는 경우와 거부되어야 하는 경우를 함께 본다.
- **`R2` 는 현재 도달 불가라서 통과한다.** 검사 대상인 `PATCH .../membership` 이
  행을 대상 블록 끝으로 **재배치**하므로 그 경로에서 연속성 오류가 나지 않는다.
  (`reorder` 도 연속성 422 를 내지만 거기엔 "편집한 행" 이라는 개념이 없다 —
  소속을 바꾸지 않으므로 조각남의 원인이 특정 행이 아니라 순서 자체다.)
  재배치 없이 소속을 받는 경로가 생기면 이 검사는 다시 의미를 갖는다.
- **정적 검사(F5 일부·F9·F10)는 문자열/AST 매칭이다.** 우회하려면 우회할 수 있다.
  F5 만은 스파이 리포지토리를 실제로 주입해 호출되는지까지 확인하므로 예외다.
- **하네스는 코드가 멈춰 있을 때만 믿을 수 있다.** 편집 중에 돌리면 반쯤 적용된
  상태를 잡아 `OPEN` 이나 `N-A` 가 뜬다. 실제로 그런 일이 있었다 — 한 번 뜬
  `OPEN` 은 재실행에서 사라졌다. 판정을 보고하기 전에 **연속 2회 같은 결과**인지
  확인할 것.

## 검사를 추가할 때

`@check("ID", "제목")` 데코레이터를 붙인 함수가 `(verdict, evidence)` 를 돌려주면
된다. 제목은 **결함**을 서술한다(고쳐진 상태가 아니라). 그래야 `OPEN` 줄이 그
자체로 버그 리포트가 된다.

서비스 시그니처는 자주 바뀌므로 직접 호출하지 말고 `call(fn, session, ...)` 을
쓴다 — 파라미터 **이름**으로 바인딩하므로, 인자가 하나 늘어난 것과 동작이 바뀐
것이 구분된다. 전자는 그냥 통과하고 후자만 판정에 잡힌다.
